Partie 01

Le dépôt devient le vôtre

Le projet vous attend ici : github.com/momo230404/post-everyday-modele. C'est un dépôt modèle : il est fait pour être copié. Une fois la copie faite, vous n'aurez plus jamais besoin du compte de qui que ce soit — ni lui du vôtre.

Trois façons de récupérer un projet existent sur GitHub, et elles n'ont pas du tout les mêmes conséquences. Une seule donne une copie sans aucun lien avec l'original.

Ce qu'on fait

Use this template

Crée un dépôt neuf, avec un historique vierge et aucun lien vers l'original. GitHub ne l'affiche pas comme une copie. Vous êtes propriétaire de tout.

Écarté

Fork

Reste rattaché au dépôt d'origine : affiché comme « forked from », rangé dans le même réseau, et vos modifications peuvent partir en proposition vers lui. On ne peut pas détacher un fork soi-même — il faut écrire au support GitHub. Ce n'est donc pas un transfert : c'est une branche de la maison de quelqu'un d'autre, et la dépendance ne s'efface jamais.

Aussi valable

ZIP + git init

Quand le projet est distribué en archive plutôt que par GitHub : décompresser, git init, pousser chez soi. Deux commandes de plus, résultat rigoureusement identique.

01 · 1Créer un compte GitHub (si vous n'en avez pas)

Sur github.com/signup. Gratuit. Activez tout de suite la double authentification : GitHub l'exige désormais pour pousser du code, et la découvrir en plein cours fait perdre vingt minutes.

01 · 2Cliquer sur « Use this template »

  • Ouvrir github.com/momo230404/post-everyday-modele.
  • Bouton vert Use this template → Create a new repository.
  • Nom : ce que vous voulez — mon-post-everyday par exemple.
  • Visibilité : Private. Votre configuration n'y sera pas, mais vos idées de contenu et vos textes clients finiront par s'y trouver.
  • Ne pas cocher « Include all branches ».
✓ Point de contrôle

Sur la page de votre nouveau dépôt, sous le titre, il ne doit y avoir aucune mention « forked from ». Et dans l'onglet Commits, un seul commit : Initial commit. C'est la preuve que vous êtes indépendant.

Partie 02

Claude Code sur votre machine

Il n'y a rien à « brancher » entre GitHub et Claude Code : Claude Code travaille sur un dossier de votre ordinateur. GitHub sert à conserver et à partager ce dossier ; le serveur sert à le faire tourner en public. Trois endroits distincts, qu'on relie avec deux commandes.

02 · 1Installer les outils

Il faut Node.js 18 ou plus récent, git, Python 3.11 ou plus, et le client GitHub.

macOS · terminal
# Homebrew, s'il n'est pas déjà là
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install node git gh python@3.11
npm install -g @anthropic-ai/claude-code
windows · powershell en administrateur
winget install OpenJS.NodeJS.LTS Git.Git GitHub.cli Python.Python.3.11
npm install -g @anthropic-ai/claude-code
  • node -v affiche v18 ou plus.
  • claude --version répond.

02 · 2Récupérer votre dépôt en local

terminal
gh auth login          # suivre les questions, choisir HTTPS

mkdir -p ~/Projets && cd ~/Projets
gh repo clone VOTRE-COMPTE/mon-post-everyday
cd mon-post-everyday

Ce dossier est désormais le vôtre, sur votre disque. C'est lui que Claude Code va ouvrir.

02 · 3Faire tourner l'application en local

Avant de toucher au serveur, vérifiez qu'elle démarre sur votre machine. Les bases SQLite se créent toutes seules au premier lancement : il n'y a aucune base de données à monter.

macOS ou linux · dans le dossier du projet
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp config.exemple.json config.json

# Le secret de session : à coller dans "secret" de config.json
./venv/bin/python -c "import secrets; print(secrets.token_hex(32))"

# Votre compte administrateur : coller le résultat dans "mdp_hash"
./venv/bin/python -c "from werkzeug.security import generate_password_hash as h; print(h('VotreMotDePasse'))"

./venv/bin/python app.py
windows · powershell, dans le dossier du projet
python -m venv venv
.\venv\Scripts\pip install -r requirements.txt
copy config.exemple.json config.json

# Le secret de session : à coller dans "secret" de config.json
.\venv\Scripts\python -c "import secrets; print(secrets.token_hex(32))"

# Votre compte administrateur : coller le résultat dans "mdp_hash"
.\venv\Scripts\python -c "from werkzeug.security import generate_password_hash as h; print(h('VotreMotDePasse'))"

.\venv\Scripts\python app.py
Mac ou Windows : la seule différence

Sur Mac et Linux, les outils de l'environnement sont dans venv/bin/ ; sur Windows, dans venv\Scripts\. Partout ailleurs dans ce guide, quand vous voyez ./venv/bin/python sur votre machine, lisez .\venv\Scripts\python si vous êtes sur Windows. Sur le serveur, ce sera toujours la forme Mac/Linux.

Dans config.json, le premier compte suffit pour commencer :

config.json · extrait
"comptes": [
  {
    "identifiant": "moi",
    "nom": "Votre prénom",
    "role": "admin",
    "mdp_hash": "scrypt:32768:8:1$...le résultat de la commande..."
  }
],
"secret": "...les 64 caractères de l'autre commande..."
✓ Point de contrôle

Ouvrez http://127.0.0.1:5010. Vous arrivez sur la page de connexion. Entrez moi et votre mot de passe. Le mode d'emploi du produit est sur /guide et ne demande aucun compte.

02 · 4Lancer Claude Code et lui faire lire le projet

dans le dossier du projet
claude
⚠ Il faut un compte Claude actif

Claude Code n'est pas gratuit : il fonctionne avec un abonnement Claude (ou une clé d'API facturée à l'usage). Créez le compte sur claude.ai avant cette étape — sinon vous installerez l'outil pour rien.

Au premier lancement, il demande de vous connecter à votre compte Claude dans le navigateur. Ensuite, tapez /init : Claude lit tout le projet et écrit un fichier CLAUDE.md qui lui servira de mémoire à chaque session. C'est ce fichier qui fait la différence entre un assistant qui redécouvre le code chaque matin et un assistant qui le connaît.

Le cycle de travail, ensuite, est toujours le même :

  • Vous décrivez ce que vous voulez, en français, sans jargon.
  • Claude modifie les fichiers ; vous relancez ./venv/bin/python app.py pour voir.
  • Quand c'est bon : git add -A && git commit -m "ce que j'ai changé" && git push.
  • Puis la mise en ligne, en partie 04.
Le réflexe qui sauve

Committez souvent, même pour de petites choses. Tant que vous avez poussé sur GitHub, aucune expérience ratée n'est définitive : git checkout . ramène tout à l'état du dernier commit.

Partie 03

Le serveur et le nom de domaine

Post Everyday écrit ses bases SQLite et ses médias sur le disque, à côté du code. Cela décide de tout le reste : il lui faut une machine dont le disque ne s'efface pas. C'est pourquoi Vercel et Netlify sont exclus — ils n'ont pas de disque durable — et c'est pourquoi on prend un VPS, une petite machine à vous.

⚠ Le fichier render.yaml est trompeur

Render est un hébergeur où l'on relie son dépôt GitHub : il construit et lance l'application tout seul, sans serveur à administrer. Le projet contient un render.yaml écrit pour lui, qui déclare un disque monté sur /var/donnees et une variable PE_DONNEES.

Mais l'application ne tient pas compte de cette variable : elle écrit toujours à côté de son code. Déployée sur Render telle quelle, elle fonctionnerait… et perdrait toutes ses données à chaque mise en ligne. Prenez un VPS, comme décrit dans la suite de cette partie.

Ce qu'il faut se procurer

QuoiChez quiQuelle taille
Le serveur (VPS)Hetzner, Hostinger, OVH, Scaleway 2 vCPU, 4 Go de RAM, 40 Go de disque — Ubuntu 24.04
Le nom de domaineOVH, Gandi, Namecheap, Cloudflare Un .com ou .fr
Le certificat HTTPSLet's Encrypt, via Caddy Automatique, rien à faire, rien à payer

Un VPS plus petit (1 vCPU, 2 Go) suffit pour démarrer. Au-delà de quelques espaces clients avec des vidéos, montez à 4 Go.

03 · 1Commander le VPS et pointer le domaine

  • Commandez un VPS sous Ubuntu 24.04 LTS. Donnez votre clé SSH si on vous la demande ; sinon notez le mot de passe root reçu par mail.
  • Notez l'adresse IP de la machine, par exemple 203.0.113.42.
  • Chez votre registrar, dans la zone DNS, créez un enregistrement : type A, nom planning, valeur l'IP du VPS. Cela crée planning.votredomaine.com.
  • Attendez que ça se propage — de 2 minutes à 2 heures.
vérifier que le domaine pointe bien
dig +short planning.votredomaine.com
# doit afficher l'IP de votre VPS, et rien d'autre

03 · 2Préparer la machine

depuis votre machine
ssh root@203.0.113.42          # votre IP

apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip git ufw

# Le pare-feu : on n'ouvre que le strict nécessaire
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
Pourquoi on n'ouvre pas le port 5010

L'application écoutera sur 127.0.0.1:5010, accessible de la machine seule. C'est Caddy qui recevra le public sur 80 et 443 et transmettra. Exposer 5010 reviendrait à publier l'application sans HTTPS, à côté de la porte d'entrée.

03 · 3Installer l'application sur le serveur

sur le serveur
mkdir -p /opt && cd /opt
git clone https://github.com/VOTRE-COMPTE/mon-post-everyday.git posteveryday
cd posteveryday

python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/pip install gunicorn

# La configuration
cp config.exemple.json config.json

# On refabrique ici le secret et le mot de passe : ce sont les mêmes
# commandes qu'en local, mais sur cette machine.
./venv/bin/python -c "import secrets; print(secrets.token_hex(32))"
./venv/bin/python -c "from werkzeug.security import generate_password_hash as h; print(h('VotreMotDePasse'))"

nano config.json               # y coller les deux résultats
chmod 600 config.json          # lisible par root seulement
nano, en trois touches

C'est l'éditeur de texte du serveur. On tape, puis : Ctrl + O puis Entrée pour enregistrer, et Ctrl + X pour sortir. Les flèches déplacent le curseur, la souris ne sert à rien.

Vous pouvez aussi reprendre celui de votre machine

Si vous avez déjà rempli config.json en local, copiez-le plutôt que de tout refaire — depuis votre ordinateur : scp config.json root@VOTRE-IP:/opt/posteveryday/config.json

⚠ Dépôt privé

Si votre dépôt est privé, git clone demandera une authentification. Le plus simple : apt install gh puis gh auth login sur le serveur, et le clone passera.

03 · 4La faire tourner en permanence (systemd)

Un service systemd relance l'application toute seule après un plantage ou un redémarrage de la machine. PE_BASE est indispensable : c'est l'adresse publique à laquelle les réseaux sociaux renverront après connexion.

sur le serveur · créer le service
cat > /etc/systemd/system/posteveryday.service <<'FIN'
[Unit]
Description=Post Everyday
After=network.target

[Service]
WorkingDirectory=/opt/posteveryday
Environment=PE_BASE=https://planning.votredomaine.com
ExecStart=/opt/posteveryday/venv/bin/gunicorn -w 2 -b 127.0.0.1:5010 \
          --timeout 600 app:app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
FIN

systemctl daemon-reload
systemctl enable --now posteveryday
systemctl status posteveryday --no-pager
  • systemctl is-active posteveryday répond active.
  • curl -I http://127.0.0.1:5010/guide répond 200.

03 · 5Le domaine et le HTTPS, avec Caddy

Caddy obtient et renouvelle le certificat Let's Encrypt tout seul. Sa configuration tient en trois lignes — c'est pourquoi il est préférable ici à nginx + certbot, qui demandent une dizaine de fichiers pour le même résultat.

sur le serveur
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

cat > /etc/caddy/Caddyfile <<'FIN'
planning.votredomaine.com {
    reverse_proxy 127.0.0.1:5010
}
FIN

systemctl reload caddy
✓ Point de contrôle

Ouvrez https://planning.votredomaine.com/guide dans un navigateur. Le cadenas doit être fermé et le mode d'emploi s'afficher. Si vous voyez une erreur de certificat, c'est que le DNS ne pointe pas encore : attendez et rechargez.

03 · 6Mettre votre nom à la place des trous

Le projet vous a été livré sans identité : ni société, ni adresse de contact, ni domaine. Ce sont des valeurs à compléter, et elles sont visibles par vos visiteurs tant que vous ne les remplacez pas.

sur le serveur · voir ce qu'il reste à remplir
cd /opt/posteveryday
grep -rn "VOTRE SOCIÉTÉ\|VOTRE-ADRESSE@exemple.fr\|votre-domaine.fr" \
     conditions.html confidentialite.html _legal_base.html guide.html tuto.html

Remplacez partout, d'un coup, par vos vraies informations :

sur le serveur · adapter les 3 valeurs
cd /opt/posteveryday
sed -i 's/votre-domaine.fr/planning.mondomaine.fr/g; \
        s/VOTRE-ADRESSE@exemple.fr/contact@mondomaine.fr/g; \
        s/VOTRE SOCIÉTÉ/Ma Société SARL/g' \
    conditions.html confidentialite.html _legal_base.html guide.html tuto.html

systemctl restart posteveryday
⚠ Les réseaux sociaux lisent ces pages

Meta, TikTok et LinkedIn réclament une page de confidentialité et des conditions à votre nom avant d'examiner une application. Des pages laissées à trous font refuser le dossier — et annoncer quelqu'un d'autre comme éditeur de votre service n'a aucune valeur juridique.

03 · 7Brancher les réseaux sociaux (plus tard)

L'application fonctionne entièrement sans cette étape : rédaction, agenda, carrousels, prompteur. Seule la publication automatique est concernée, et elle répond 501 tant que les applications éditeurs n'existent pas.

Ce n'est pas un défaut : chaque réseau exige une application déclarée et validée chez lui, au nom du client ou de l'agence. Il faudra créer une app chez Meta, TikTok, LinkedIn et Google, puis coller les identifiants dans config.json. Comptez plusieurs jours de validation côté plateformes. À traiter une fois que le reste tourne.

⚠ L'adresse de retour doit correspondre

Dans chaque application éditeur, l'URL de redirection doit être exactement celle de votre domaine — la même que PE_BASE. Une erreur ici, et la connexion échoue sans message clair.

Partie 04

Vivre avec : mises à jour et sauvegardes

04 · 1Mettre en ligne ce que vous avez codé

Vous travaillez en local avec Claude Code, vous poussez sur GitHub, puis vous tirez sur le serveur. Deux commandes.

sur le serveur
cd /opt/posteveryday
git pull
./venv/bin/pip install -r requirements.txt   # si les dépendances ont bougé
systemctl restart posteveryday
Pourquoi config.json ne pose pas de problème

Il est dans le .gitignore : git pull ne l'écrase jamais. Vos clés et vos comptes restent en place à chaque mise à jour. Même chose pour les bases .db et le dossier medias/.

04 · 2Sauvegarder, parce que rien ne le fait pour vous

Le dépôt GitHub ne contient aucune donnée : ni les bases clients, ni les médias, ni la configuration. Si le disque du VPS meurt, tout est perdu. Posez cette sauvegarde quotidienne dès le premier jour.

sur le serveur
mkdir -p /opt/sauvegardes

cat > /opt/sauvegarder.sh <<'FIN'
#!/bin/bash
# Les donnees de Post Everyday : bases, medias, configuration.
cd /opt/posteveryday || exit 1
H=$(date +%Y%m%d-%H%M)
tar czf "/opt/sauvegardes/pe-$H.tgz" \
    --exclude='venv' --exclude='__pycache__' \
    config.json espaces.json medias/ *.db 2>/dev/null
# On garde 14 jours, pas plus : le disque n'est pas extensible.
find /opt/sauvegardes -name 'pe-*.tgz' -mtime +14 -delete
FIN

chmod +x /opt/sauvegarder.sh
/opt/sauvegarder.sh && ls -lh /opt/sauvegardes

# Tous les jours à 3 h du matin
(crontab -l 2>/dev/null; echo "0 3 * * * /opt/sauvegarder.sh") | crontab -
⚠ Une sauvegarde sur la même machine n'est pas une sauvegarde

Si le disque lâche, elle part avec. Copiez l'archive ailleurs — votre ordinateur, un espace de stockage. La commande, à lancer depuis chez vous : scp root@VOTRE-IP:/opt/sauvegardes/pe-*.tgz ~/Sauvegardes/
